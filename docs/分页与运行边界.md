# 分页与运行边界

本地 stdio、单用户、单项目是 0.1.0 的部署范围。以下行为来自源码审查和隔离测试，不代表产品效果评测或完整并发安全证明。

## 可运行的客户端示例

先按 README 安装依赖并生成演示配置，在仓库根目录执行：

```powershell
uv run --frozen python -X utf8 scripts/paginate_records.py --config config/demo.local.toml --source demo-events --page-size 2
```

示例通过官方 SDK 启动独立 stdio 服务，明确查询选定源中的全部目标；显示来源和警告。输入 `n` 下一页、`p` 上一页、`q` 退出。演示配置的数据是合成测试数据。

- 首次调用不传游标，创建新快照。还有结果时返回 `next_cursor`；末页为 `null`。
- 后续页沿用返回的 `normalized_plan` 和 `next_cursor`。相对时间已固定为绝对范围，不能重新解释“昨天”等表达式。
- 历史页（包括首屏）缓存在示例客户端内，回退不调用服务。客户端缓存会占用内存，关闭示例后丢失；它与服务缓存的预算不同。
- 首屏没有指向自身的游标。保存第二页的请求游标可重访第二页，但无法据此返回原快照首屏。
- 示例遇到错误便停止，不自动拼接新旧快照。重新运行会创建新快照，结果可能变化。
- 这是最小浏览示例，不包含任务句柄管理、认证扩展或完整界面。

## TTL、LRU 与容量

`snapshot_ttl_seconds` 默认 300 秒，可配置为 1–3600 秒。有效期使用单调时钟，从创建快照开始计算；访问只更新 LRU 顺序，不续期。清理为惰性清理，过期不等于立即释放内存。

`snapshot_cache_bytes_max` 默认 50 MiB，可配置。单快照估算权重超限返回 `snapshot_too_large`；新快照入缓存前先清理过期项，再按最近访问顺序淘汰旧项。即使 TTL 未到，快照也可能被容量淘汰。

预算基于记录对象的估算权重，不是进程 RSS 上限。解析临时对象、新记录、快照元数据及缓存管理开销可能增加内存峰值。没有测量证据时，不应把惰性清理直接归因为缓存预算超限。

## 游标错误与恢复

| 情况 | 通常返回 | 调用方处理 |
|---|---|---|
| 签名、任务绑定或作用域不匹配 | `cursor_invalid` | 检查任务和请求，不能自行篡改游标 |
| 规范化计划不同 | `cursor_query_mismatch` | 沿用上页返回的计划 |
| 快照过期、被淘汰或缓存被替换 | `cursor_expired` | 明确结束旧分页，再开始新查询 |
| 当前实例未授权该源 | `access_denied` | 检查启动配置，不扩大访问范围 |

错误按校验顺序返回。完整重建 Application 会更换签名密钥；旧游标在前置校验通过后返回 `cursor_invalid`。若绑定的 ephemeral 任务已丢失，则可能先返回 `task_not_found`。仅替换 RecordSource 且保留签名器时，缺失的旧快照返回 `cursor_expired`。

## 配置与并发

配置启动时加载，修改磁盘 TOML 不改变已有实例。重启后加载新配置；ephemeral 任务及快照缓存丢失，persistent 任务仍受原有效期和作用域约束。当前没有热更新接口。

`Application.call` 在参数验证后获取全局 RLock，保护业务处理、缓存修改及结果构造。`ContextStore` 的常规数据库方法还有自身锁；直接调用 RecordSource 不具有独立的缓存锁保护。

查询 deadline 在获取应用锁后创建，不包含排队时间；日志 `elapsed_ms` 从获取锁前开始计时，包含锁等待。deadline 是协作式检查，不保证强制中断阻塞系统调用，也不是客户端端到端时限。单用户智能体仍可能并行调用工具，锁竞争程度需实测。

## 本轮回归证据

新增测试位于 `tests/test_review_regressions.py`：实际 TOML 重载、锁获取与 deadline 顺序、LRU 与 FIFO 区别、固定 TTL、历史游标复用及实例替换错误码。`tests/test_pagination_example.py` 通过真实 MCP 子进程验证下一页、返回首屏、重访历史页和末页处理。

测试使用临时目录和合成数据，不需要重启用户宿主管理的服务。有限场景通过不代表所有输入、所有并发状态或真实宿主产品效果都已验证。真实任务体验评测仍按 `evals/README.md` 执行。
